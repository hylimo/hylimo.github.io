UML Class Diagram ​

To create a UML class diagram, one uses the classDiagram diagram function:

HyLiMo
classDiagram {
    // define elements
}

All elements described below are also available in the general UML diagram.

Elements ​

The following elements are supported:

class ​

Creates a new class element, with the defined name, and optional properties and operations:

Click to interact

Note that properties and functions are defined declaratively, and are not executable code. Thus, e.g. if x is a defined variable, the property is still named x, not the value of x. Five different types of visibility are supported:

  • public
  • private
  • protected
  • package
  • default (no visibility)

Connections / Associations ​

Connections / Associations are created using a PlantUMl-inspired operator syntax. Both sides of the operand can be either points, or canvasElemments, and thus classes, interfaces, packages or comments. The following operators are supported:

  • -- for a simple association
  • --* for a composition
  • --<> for an aggregation
  • extends for a generalization
  • implements for an implementation
  • ..> for a dependency
  • --! for an association not-navigatable in one direction
  • --> for an association navigatable in one direction
  • ... and several combinations of the above, e.g, !--!, *-->, ...

Connections between nested elements ​

A connection can be written in any block, including inside a nested element. It is placed in the innermost element containing both of its ends, so connecting the contents of two different packages does not have to happen at the top level:

Click to interact

Elements themselves always stay in the block they are written in. Therefore, a nested element cannot be positioned relative to an element outside its parent, e.g. using rpos.
